Process Architecture & Execution Topology

WebhookProcessor is a cloud webhook router and event translation gateway running on Render. It ingests external events from Cal.com, Notion, Gmail Pub/Sub, and Simple triggers, routes them through domain processors, validates schemas via Pydantic, and executes dual downstream actions: FreeMobile SMS notifications and GitHub Actions repository dispatch.

GET/ GET/health GET/webhook POST/webhook
Environment: Render Web Service
Runtime: Python / FastAPI
Base URL: hook2sms.onrender.com
Error Channel: FreeSMS Alert [SMS_PREFIX]

Detailed Step-by-Step Execution

1
Ingress & Endpoint Routing
FastAPI receives the HTTP request at https://hook2sms.onrender.com. Distinguishes between health probes, verification challenges, and live event webhooks.
GET /health -> {"status": "ok"}
POST /webhook -> parse payload
2
Processor Selection
Iterates over registered processors (CalWebhookEvent, NotionWebhookProcessor, GmailWebhookProcessor, SimpleWebhookProcessor) evaluating can_handle(payload).
for proc in WEBHOOK_PROCESSORS:
if proc.can_handle(payload): break
3
Validation & Decision
Pydantic validates input attributes and triggers should_enable_workflow(payload). Formats outgoing SMS content with SMS_PREFIX = "Hook2SMS service : \n".
processor.model_validate(payload)
processor.process_workflow()
4
Downstream Dispatch & Alerts
Sends FreeSMS message and triggers GitHub Actions if configured. If errors occur or no processor matches, notify_error() sends a failure alert with a 60s cooldown cache.
send_sms() & trigger_github_action()
notify_error(context="POST /webhook")
